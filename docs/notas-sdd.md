\# Notas sobre Spec-Driven Development



Una spec describe qué necesita hacer una funcionalidad y por qué se necesita, sin entrar todavía en decisiones técnicas.



El plan define cómo se va a construir técnicamente lo que solicita la spec.



Las tasks dividen el plan en trabajos pequeños, claros y verificables.



Primero se define y revisa lo que se quiere construir, después se decide cómo implementarlo y finalmente se divide el trabajo en tareas.



Este flujo permite que el código se desarrolle a partir de requisitos claros y que posteriormente se pueda comprobar si cumple lo especificado.
